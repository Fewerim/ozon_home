# Корзина и каталог товаров

Проект состоит из двух сервисов:

- **product-service** — gRPC-сервис на порту `50051`. При запуске загружает товары из `product-service/data.json` в память. Предоставляет методы `GetProduct` (поиск по SKU) и `ListProducts` (список товаров по страницам, отсортированный по SKU). Для списка значения по умолчанию: `limit=20`, `offset=0`.
- **cart** — HTTP-сервис на порту `8080`. Хранит корзины в памяти, проверяет наличие товара через gRPC перед добавлением, суммирует количество повторно добавленного товара и возвращает корзину с общей стоимостью и сортировкой по SKU. HTTP-запросы логируются middleware.

Данные корзин теряются после перезапуска. Swagger UI не реализован.

При чтении корзины `cart` параллельно запрашивает актуальные данные каждого товара в `product-service`. У всей пачки запросов общий таймаут 20 секунд. Ответ сортируется по SKU, а `total_price` пересчитывается по актуальным ценам и сохранённому количеству товаров. Если хотя бы один товар больше не найден, сервис возвращает HTTP `412` без частичной корзины.

Доступ к корзинам в памяти защищён `sync.RWMutex`: добавление выполняется под блокировкой записи, чтение — под блокировкой чтения. Полученный снимок корзины обрабатывается без удержания блокировки во время gRPC-запросов.

## Запуск

Из каталога `task_2`:

```bash
make run-all
```

Для повторной генерации Go-кода из `.proto` нужен `protoc` и плагины `protoc-gen-go`, `protoc-gen-go-grpc`:

```bash
make generate
```

## Тестирование

Из каталога `task_2`:

```bash
make test       # юнит-тесты обоих сервисов
make test-race  # те же тесты с race detector
```

Юнит-тесты `cart` используют подставной каталог товаров и не требуют запуска `product-service`. Интеграционные тесты находятся в `test/` и скрыты за билд-тегом `api`. Они обращаются к работающим сервисам по gRPC и HTTP; подключения к gRPC вынесены в `test/connection.go`.

Для интеграционных тестов запустите сервисы в одном терминале, а тесты — в другом:

```bash
make run-all
# в другом терминале:
make test-api
```

`make test-api` запускает тесты без кэша результатов (`-count=1`). Для проверки корзины каждый запуск использует нового пользователя, поэтому результат не зависит от данных прошлых запусков.

## Примеры запросов

```bash
# Получить товар
grpcurl -plaintext -d '{"sku":1076963}' localhost:50051 productService.ProductService/GetProduct

# Получить первую страницу каталога; следующая — offset=20
grpcurl -plaintext -d '{"offset":0,"limit":20}' localhost:50051 productService.ProductService/ListProducts

# Добавить две единицы товара в корзину пользователя 1007
curl -i -X POST localhost:8080/user/1007/cart/1076963 \
  -H 'Content-Type: application/json' -d '{"count":2}'

# Получить корзину
curl -i localhost:8080/user/1007/cart
```

Некорректные параметры дают HTTP `400` (для gRPC — `InvalidArgument`), отсутствующая или пустая корзина — `404`, а добавление или чтение несуществующего товара — `412`. HTTP-ошибки возвращаются текстом.
